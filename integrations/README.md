# MarkHub on www.solix.com

MarkHub runs **alongside** the current lead flow. solix.com's forms keep sending leads, deals and companies to
Digiprise (the CRM of record) exactly as today. MarkHub receives a copy of each lead to:

- score it
- link it to the visitor's browsing
- map it to a product line

MarkHub sends **no** second sales alert and **no** second download email for solix.com leads.

| Piece | Where | What it does |
|---|---|---|
| WordPress plugin | `integrations/wordpress/markhub-connector/` | Forwards form submissions server to server (demo, contact sales, contact questions, gated downloads), with a retry queue |
| GTM tag | `integrations/solixcom/markhub-tag.js`, served at `/api/markhub.js` | Cookie banner, then product-interest tracking; stamps the visitor id into forms |
| Sol knowledge | `site_knowledge.py` | Sol learns solix.com's pages, KB, glossary and leadership lessons, synced daily |
| CMS import | MarkHub › Content › Import (existing) | Copies white papers, datasheets, case studies, ebooks and KB articles into the MarkHub CMS |

## 1. MarkHub (Render)

Deploy this branch. `render.yaml` adds the following:

- `CORS_ORIGINS` gains `https://www.solix.com` and `https://solix.com`.
- `WP_INTAKE_SECRET` is generated by Render. If the service was created before this key existed in `render.yaml`, add
  it by hand with a long random value. Copy it for step 2.
- `SOL_WORDPRESS_SITES=https://www.solix.com`. The first sync starts about 90 seconds after boot. It takes about a
  minute and stores about 1,700 pages.
- `WP_INTAKE_ALERTS` is left unset. Set it to `1` only when MarkHub, rather than Digiprise, should alert sales.

## 2. WordPress plugin

1. Zip the `markhub-connector` folder.
2. In WordPress, go to Plugins › Add New › Upload, then activate it.
3. Go to Settings › MarkHub:
   - API address: `https://solix-backend-mf5w.onrender.com`
   - Intake key: the `WP_INTAKE_SECRET` value
   - Tick **Forward submissions**
4. Click **Test connection**. It should say "Connected: MarkHub accepted the key".

   (The first try can take up to a minute if the free-tier API is asleep.)

You can set these in `wp-config.php` instead of the settings page: `MARKHUB_API_URL`, `MARKHUB_INTAKE_KEY` and
`MARKHUB_ENABLED`.

The plugin reads each POST only after the theme has handled it, so the site's own email and Digiprise hand-off are
unchanged. If the theme answers with an error (validation or reCAPTCHA), nothing is forwarded. If MarkHub can't be
reached, the lead is queued and retried every five minutes for up to a week. The settings page shows the last 25
forwards, listing only the email domain.

Forms recognised today, by field names found on the live site in November 2026:

| Form | Page | Detected by | MarkHub type |
|---|---|---|---|
| request-demo | /products/request-demo/ | `demo_email` | demo |
| contact-sales | /company/contact-sales/ | `cts_email` | contact |
| contact-question | /company/contact-sales/ (questions box) | `full_name` + `email` + `msg` | contact |
| gated-download | /resources/lg/... | `new_email` | download |

To add a form, use the `markhub_connector_forms` filter in the child theme's `functions.php`.

## 3. Google Tag Manager (GTM-53944LZ)

1. Add a tag: **Custom HTML**, trigger **All Pages**:

   ```html
   <script src="https://solix-backend-mf5w.onrender.com/api/markhub.js" async></script>
   ```

2. **Gate the existing tags on the same choice.** solix.com currently loads Clarity, LinkedIn Insight and GTM tags
   with no consent banner. The MarkHub tag pushes `{event: "markhub_consent", analytics: "granted" | "denied"}` to the
   dataLayer, and updates Google Consent Mode when `gtag` is present. Do the following:
   - Create a Custom Event trigger `markhub_consent` with the condition `analytics` equals `granted`.
   - Fire Clarity, LinkedIn Insight and similar tags on that trigger instead of All Pages.
   - For returning visitors the event fires on every page load, so no extra setup is needed.
3. Add a "Cookie settings" link in the footer: `<a href="#" onclick="markhub.openConsent();return false">Cookie settings</a>`.
4. Publish.

Staff can open any page with `?solix_internal=1` once. That browser is then left out of every metric.

## 4. Check it end to end

1. In a private window, open www.solix.com. The banner shows. Click **Accept analytics**.
2. Visit a product page (for example /products/application-retirement-solution/) for about a minute, then submit
   the demo form with a test address on a domain listed as internal (Admin › Settings › Internal traffic). This keeps
   it out of metrics.
3. In MarkHub:
   - The submission shows in the Inbox with source `solix.com`.
   - The lead shows the browsing and Application Retirement interest.
   - In WordPress, Settings › MarkHub shows "sent".
4. Ask Sol something only solix.com covers, such as "What is HIPAA compliance?". The answer cites a www.solix.com
   page. Sync status: `GET /api/admin/sol/site-knowledge`. Force a sync: `POST /api/admin/sol/site-knowledge/sync`.

## 5. CMS import (optional)

Go to MarkHub › Content › Import, then choose source **WordPress** with URL `https://www.solix.com`:

- **Post types:** `pages`, `kb`
- **Include:** `/resources/white-papers/,/resources/case-studies/,/resources/datasheets/,/resources/ebooks/,/kb/`
- **Exclude:** `/resources/lg/,/answers/`
- **Status:** **Draft**

Publishing puts the items on the MarkHub website and in Sol, so review them first.

A dry run on 26 Nov 2026 found 443 items: 84 white papers, 53 datasheets, 27 case studies, 17 ebooks and 262 KB
articles. It imports the landing-page text. The PDFs stay behind solix.com's own forms.

## Notes

- Product mapping: solix.com URLs that differ from MarkHub's product slugs are mapped in `scoring.SOLIXCOM_PATHS`,
  and industry pages in `SOLIXCOM_INDUSTRIES`. Add new product pages there.
- What Sol skips, to keep its index useful and inside 512 MB:
  - About 2,000 auto-generated `/answers/` pages and the 27,000-page `answer` post type.
  - Gated `/resources/lg/` duplicates.
  - solix.com "posts", which are links to external news sites.

  With all of that skipped, Sol's index grows by about 4,900 chunks and about 24 MB.
- The client IP from WordPress is used only to spot office traffic. It is never stored.
